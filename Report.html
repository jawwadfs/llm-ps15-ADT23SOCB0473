1. Problem Statement

University libraries house thousands of physical volumes across multiple floors. Students frequently face difficulty locating the right reference books matching their immediate coursework, semester examinations, or interview preparation goals. Existing library computer catalogues (OPACs) perform only rigid exact-string lookups and fail when students search with conversational needs (e.g., "friendly book to start Python" or "books on DBMS normalization"). This project develops an intelligent Library Assistant Chatbot that filters a curated campus catalogue CSV by keyword and topic, queries Google Gemini 2.5 Flash, and returns structured pedagogical recommendations for the top 3 books with exact shelf locations and available copies.

2. Tools & Model

  • Language & Runtime: Python 3.9+
  • Data Processing: pandas for tabular catalogue loading, multi-field token filtering, and inventory tracking.
  • LLM & API: Google Gemini 3.8 Flash via API (temperature=0.2, responseMimeType="application/json") for deterministic, structured recommendations.
  • UI Framework: Streamlit (featuring st.chat_message, st.chat_input, live catalogue viewer, real-time book reservation, and analytics dashboard).
  • Environment Management: python-dotenv for secure API key injection.

3. Procedure (Step-by-Step Implementation)

  1. Environment Setup: Initialized a dedicated Python virtual environment, configured .gitignore to protect secret API keys, and prepared repository structure.
  2. Library Dataset Creation: Curated data/library_catalogue.csv containing 25+ academic textbooks across Computer Science, AI, Databases, Networks, Mathematics, and DevOps with fields: book_id, title, author, genre_category, topic_keywords, edition_year, shelf_location, available_copies, and brief_summary.
  3. Keyword Pre-Filtering Engine: Developed filter_catalogue_by_keyword() using tokenization and multi-field scoring (Title: +5, Author: +5, Category: +3, Topics: +3, Summary: +1). This retrieves the top 6 candidate rows to bound context length and eliminate hallucinations.
  4. Prompt Engineering & JSON Schema: Drafted a persona-guided prompt directing the LLM to select the top 3 books, explain why they suit the student, identify reading level, and provide shelf locations in strict JSON.
  5. API Integration & Offline Fallback: Connected to Gemini 2.5 Flash with fallback to a deterministic rule-based engine ensuring zero downtime during offline viva demonstrations.
  6. Streamlit User Interface: Built a rich chat UI with quick query chips, styled recommendation cards, live copy count badges, and an interactive catalogue browser.
  7. Testing & Report Compilation: Validated system behavior against 5 distinct student query test cases and generated documentation.

4. Final Prompt Used

You are the intelligent College Library Assistant Bot. A student came to the desk with this query: "{student_query}" Candidate books retrieved from catalogue: {candidate_str} === INSTRUCTIONS === 1. Select the top 3 most relevant books from the candidates for this student. 2. For each recommended book, provide: why it fits their request (clear pedagogical explanation), shelf location, available copies, and ideal reading level (Beginner/Intermediate/Advanced). 3. Conclude with 1 helpful librarian tip. Format output strictly as a valid JSON object matching the required schema.

5. Prompt Refinement & Iterative Improvement

Initial Prompt Flaw: The initial prompt asked the model for general recommendations in plain text. In preliminary runs, the LLM frequently hallucinated popular textbooks that our campus library did not own, and regularly omitted physical shelf locations and live copy counts.

Iterative Improvement Made: Constrained the prompt by injecting candidate rows extracted directly from library_catalogue.csv and configured native JSON output mode (response_mime_type="application/json"). This enforced 100% adherence to actual library holdings, eliminated hallucinations, and allowed the Streamlit UI to reliably render styled book cards.

7. Challenges Faced & Solutions Implemented

  • Challenge 1: Freeform Markdown Code Fence Errors: LLMs often wrap JSON outputs with ```json ... ```, causing json.loads() exceptions. Solution: Implemented a regex cleaning function clean_json_string() to automatically strip leading and trailing markdown backticks before deserialization.
  • Challenge 2: Irrelevant Search Candidates: Direct string matching failed when queries contained conversational stop words (e.g. "can you give me some books on..."). Solution: Added an English stop-word filter and weighted scoring across titles (+5), authors (+5), categories (+3), and keyword tags (+3).
  • Challenge 3: Offline Demonstration for Viva: Risk of network drops or API quota exhaustion during classroom evaluation. Solution: Engineered an Offline Demo Mode toggle in the sidebar that executes local heuristic scoring and outputs formatted recommendations with zero API dependency.

8. Conclusion & Future Scope

What Works: Robust keyword pre-filtering, 100% adherence to campus catalog stock, rich visual display of shelf locations and copies, and conversational explanations tailored to student experience levels. What Doesn’t: Currently relies on token overlap; misspellings or uncommon synonyms require exact substring matches. Future Improvement: Implement dense vector embeddings (using FAISS and text-embedding-004) for semantic vector search and integrate with the college circulation SQL database for automated book reservations.
